Runtime DFU cho STM32F427VIT6

Tóm tắt triển khai và manual sử dụng

Ngày: 07/10/2026   |   USB OTG_HS controller + internal FS PHY

Mục tiêu: cập nhật firmware khi application đang chạy qua USB composite, không dùng System Memory bootloader của ST và không cần thay đổi chân BOOT0.

1. Những gì đã triển khai

  • Bật DFU class trong USB composite hiện có (CDC + UVC + DFU).
  • Thêm runtime_dfu.c/.h để nhận firmware vào vùng staging ở nửa flash trên.
  • Giới hạn erase/write/read chỉ trong vùng staging; không cho DFU ghi đè image đang chạy.
  • Ghi metadata gồm magic, kích thước image, CRC32 và cờ valid.
  • Kiểm tra vector table và CRC32 trước khi chấp nhận image.
  • Sau DFU manifestation, application reset; routine đặt trong .RamFunc copy image staging về vùng application rồi reset lần cuối.
  • Thêm source runtime DFU vào CMake và thêm prototype MX_USB_DEVICE_Init() qua header USB device.
  • Giữ USB ở USB_OTG_HS với USB_OTG_EMBEDDED_PHY, tốc độ Full Speed.

3. Layout flash mới

VùngĐịa chỉKích thướcMục đích

DFU staging0x08100000 - 0x081DFFFF896 KiBImage mới nhận qua USB.

Linker hiện dùng:

RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 192K
CCMRAM(xrw) : ORIGIN = 0x10000000, LENGTH = 64K
FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 1024K
Firmware application không được vượt quá 1 MiB. File firmware dùng để nạp qua DFU phải tương ứng với image bắt đầu tại 0x08000000.

5. Manual build và nạp firmware

Build

Build project bằng CMake/STM32CubeIDE như bình thường. Build đã được kiểm tra thành công:

FLASH: 140780 B / 1 MB
RAM:    92328 B / 192 KB
Result: success

Nạp firmware lần đầu

Vì runtime DFU cần có mặt trong image hiện tại, lần đầu hãy nạp image bằng ST-Link/debugger:

  1. Build application.
  2. Nạp file ELF/HEX/BIN vào địa chỉ 0x08000000.
  3. Reset MCU, kết nối USB vào chân PB14 = DM, PB15 = DP.
  4. Kiểm tra thiết bị composite đã enumerate với CDC, UVC và DFU.

Update qua runtime DFU

  1. Giữ nguồn MCU và giữ kết nối USB.
  2. Dùng host DFU gửi firmware mới qua interface DFU của thiết bị composite.
  3. Firmware sẽ được ghi vào 0x08100000, không ghi trực tiếp vào vùng đang chạy.
  4. Khi host kết thúc manifestation, thiết bị sẽ reset. Đây là reset về application, không phải nhảy vào bootloader ST.
  5. Trong lần khởi động tiếp theo, firmware được verify CRC rồi copy về 0x08000000.
  6. Thiết bị reset lần nữa và chạy image mới.

Ví dụ với dfu-util

dfu-util -l
dfu-util -d <VID>:<PID> -a 0 -D build\Debug\STM32F427VIT6.bin

VID/PID và alternate setting phải lấy từ descriptor thực tế của firmware bằng dfu-util -l. Nếu host yêu cầu địa chỉ, dùng vùng staging theo descriptor, không dùng địa chỉ vùng application đang chạy.

6. Điều kiện và giới hạn

  • Image tối đa: 896 KiB theo vùng staging được định nghĩa hiện tại.
  • Application tối đa: 1 MiB.
  • Không ngắt nguồn trong lúc đang copy staging về application.
  • Routine copy được đặt trong RAM để không execute từ flash đang program.
  • CRC32 hiện bảo vệ lỗi truyền/ghi; chưa phải chữ ký số chống firmware giả mạo.
  • Không được dùng vùng 0x081E0000 cho dữ liệu khác vì đây là metadata.
  • USB internal PHY chỉ chạy Full Speed; muốn High Speed 480 Mbps cần ULPI PHY ngoài.

7. Kiểm tra sau khi update

  1. Thiết bị vẫn enumerate USB sau reset.
  2. CDC mở được và phản hồi.
  3. UVC tiếp tục stream camera.
  4. Firmware version/marker trong image mới đúng.
  5. Không có lặp reset liên tục nếu CRC hoặc vector table không hợp lệ.
Kết quả: Runtime DFU đã được tích hợp vào workspace, build pass, không đổi BOOT0, không sử dụng bootloader ST và có staging/metadata layout rõ ràng trong flash.
