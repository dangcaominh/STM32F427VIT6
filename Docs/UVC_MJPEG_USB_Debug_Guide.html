STM32F427: truyền MJPEG qua USB UVC

Flow khởi tạo, USB enumeration, descriptor, interrupt và phương pháp debug từng bước

Tài liệu bám theo project STM32F427VIT6, USB Composite CDC + UVC, OV5640, DCMI và USB OTG HS peripheral chạy Embedded PHY ở Full-Speed.

Mục tiêu: hiểu vì sao Windows Camera gọi được SOF nhưng chưa gọi VIDEO_Itf_Data(), và biết đặt breakpoint ở đúng tầng thay vì dừng liên tục trong SOF.

2. Các khái niệm cần nắm

2.1 Endpoint

Endpoint là kênh logic giữa host và device. Hướng truyền nằm trong bit 7 của địa chỉ:

Địa chỉÝ nghĩa
0x00Control OUT, luôn thuộc endpoint 0.
0x80Control IN, endpoint 0.
0x81Endpoint 1 IN.
0x83Endpoint 3 IN. Composite có thể remap UVC sang địa chỉ này.

Trong code, callback nhận epnum không có bit hướng. Vì vậy 0x83 & 0x7F = 3.

2.2 Transfer type

LoạiDùng choĐặc điểm
ControlEnumeration, descriptor, UVC probe/commit, interfaceEndpoint 0, có request/response và status stage.
BulkCDC dataĐảm bảo dữ liệu, không đảm bảo latency.
InterruptCDC command/HIDPolling định kỳ, gói nhỏ.
IsochronousUVC videoƯu tiên bandwidth/đúng nhịp; mất gói không retransmit.

2.3 Descriptor

Descriptor là dữ liệu cấu hình mà device trả cho host. Host không tự đoán camera; nó đọc descriptor để biết có bao nhiêu interface, endpoint, format, kích thước và frame interval.

DescriptorVai trò trong project
DeviceVID/PID, USB version, số configuration.
ConfigurationTổng số interface, power, tổng độ dài descriptor.
Interface Association (IAD)Gom VideoControl + VideoStreaming thành một chức năng camera.
VC interfaceĐiều khiển UVC.
VS interface alt 0Streaming chưa mở endpoint.
VS interface alt 1Streaming, có ISO IN endpoint.
Format MJPEG / FrameQuảng bá 320x240 và frame interval.
EndpointĐịa chỉ, ISO, max packet size, interval.

2.4 FIFO và PMA

FIFO USB OTG: STM32F4 OTG HS có Rx FIFO và Tx FIFO trong USB core. Với project này, HAL_PCDEx_SetTxFiFoInBytes() cấu hình Tx FIFO cho các endpoint IN. UVC phải có FIFO đủ cho packet ISO.

PMA: Packet Memory Area là vùng RAM đặc biệt của USB FS peripheral trên một số STM32 (đặc biệt USB FS device IP). PMA được dùng để chứa packet endpoint và được cấu hình bằng HAL_PCDEx_PMAConfig(). Project này dùng USB_OTG_HS + embedded PHY, nên dùng OTG FIFO, không dùng PMA cho đường UVC đang chạy.

Phân biệt: DCMI DMA chép pixel/JPEG từ OV5640 vào cameraData[]. USB OTG DMA (nếu bật) là cơ chế khác. Tắt USB OTG DMA không tắt DCMI DMA.

3. Flow khởi tạo từ reset tới USB ready

  1. HAL_Init(): SysTick, HAL.
  2. SystemClock_Config(): clock MCU.
  3. MX_USB_OTG_HS_PCD_Init(): cấu hình OTG HS peripheral. Project hiện dùng PCD_SPEED_FULL, embedded PHY, SOF enable.
  4. MX_USB_DEVICE_Init():
    • USBD_COMPOSITE_Mount_Class() ghép CDC/UVC descriptor và remap interface/endpoint.
    • USBD_Init(..., DEVICE_HS) liên kết USB device core với PCD.
    • USBD_RegisterClass(..., USBD_COMPOSITE).
    • USBD_VIDEO_RegisterInterface(...) gắn callback ứng dụng.
  5. LCD_Init(), Camera_Init_OV5640(), bật DCMI interrupt và bắt đầu DCMI DMA snapshot.

4. Enumeration và UVC negotiation

USB reset
→ GET_DESCRIPTOR(Device)
→ SET_ADDRESS
→ GET_DESCRIPTOR(Configuration)
→ SET_CONFIGURATION(1)
→ UVC GET_CUR/GET_MIN/GET_MAX(PROBE)
→ UVC SET_CUR(PROBE)
→ UVC GET_CUR(PROBE)
→ UVC SET_CUR(COMMIT)
→ SET_INTERFACE(VideoStreaming, alt 1)
→ SOF bắt đầu stream

Request control đi qua:

OTG_HS_IRQHandler()
  → HAL_PCD_IRQHandler()
    → HAL_PCD_SetupStageCallback()
      → USBD_LL_SetupStage()
        → USBD_COMPOSITE_Setup()
          → USBD_VIDEO.Setup()

Điều kiện để UVC chuyển sang READY nằm trong USBD_VIDEO_Setup(): device phải CONFIGURED, interface phải là VS interface, và wValue == 1.

5. Flow SOF và gửi gói đầu tiên

USB frame tick (Full-Speed: mỗi 1 ms)
  → HAL_PCD_SOFCallback()
    → USBD_LL_SOF()
      → USBD_COMPOSITE_SOF()
        → USBD_VIDEO.SOF()
          nếu uvc_state == READY:
             USBD_LL_Transmit(UVC_IN_EP, payload_header, 2)
             uvc_state = STREAMING

SOF chạy liên tục kể cả khi uvc_state == STOP. Vì vậy breakpoint trong SOF sẽ dừng liên tục nhưng không có nghĩa video đang truyền.

6. Flow IN transfer complete tới VIDEO_Itf_Data()

USB host hoàn tất ISO IN transfer
  → OTG_HS_IRQHandler()
    → HAL_PCD_IRQHandler()
      → HAL_PCD_DataInStageCallback(hpcd, epnum)
        → USBD_LL_DataInStage()
          → USBD_COMPOSITE_DataIn()
            nếu epnum == (UVC_IN_EP & 0x7F):
              → USBD_VIDEO.DataIn()
                nếu uvc_state == STREAMING:
                  → VIDEO_Itf_Data(&pbuf, &psize, &pcktidx)
                  → thêm UVC header
                  → USBD_LL_Transmit() packet kế tiếp

Nếu VIDEO_Itf_Data() không chạy, hãy debug từ dưới lên:

  1. USBD_VIDEO_SOF() có chuyển STOP → READY → STREAMING không?
  2. USBD_LL_Transmit() có được gọi với đúng UVC_IN_EP không?
  3. HAL_PCD_DataInStageCallback() có chạy không?
  4. epnum có bằng UVC_IN_EP & 0x7F không?
  5. USBD_COMPOSITE_DataIn() có route sang USBD_VIDEO.DataIn() không?

Trong cấu hình composite hiện tại, UVC thường được mount trước CDC nên interface video thường là 0/1 và UVC endpoint thường bắt đầu ở 0x81. Tuy nhiên hãy dùng giá trị runtime; không giả định endpoint là 0x81 hoặc 0x83.

10. Lưu ý bandwidth

USB Full-Speed có frame 1 ms. Project đang dùng embedded PHY và PCD_SPEED_FULL, vì vậy bắt đầu với 320x240 MJPEG ở 5 FPS. JPEG thực tế phải nhỏ hơn buffer camera và được truyền qua nhiều ISO packet. 60 FPS ở cấu hình Full-Speed là không thực tế.

11. Tóm tắt một câu

SOF chỉ là nhịp đồng hồ; DATA chỉ chạy sau khi host đã SET_INTERFACE alt 1 và USB controller hoàn tất gói ISO IN đầu tiên. Khi debug, tìm request SET_INTERFACE trước, sau đó theo dõi DataIn callback và endpoint number.
